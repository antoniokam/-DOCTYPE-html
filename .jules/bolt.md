## 2024-05-28 - Regex Recompilation & CRLF Preservation in VSME Tool
**Learning:** The `!DOCTYPE html.html` application suffered from render loop overhead because `isDataEmpty` was redefined inside a frequently executed scope (e.g., inside `.map` or `.forEach` during report generation) using an inline regex `/<(.|\n)*?>/g` that is prone to catastrophic backtracking and recompilation. Furthermore, the file uses CRLF line endings, and simple `sed` or standard python `open('w')` writes risk corrupting the file structure.
**Action:** Always hoist static regexes (like `/<[^>]*>/g`) and pure helper functions to the global/module scope to prevent recompilation and recreation overhead during render loops. Always modify `!DOCTYPE html.html` using Python scripts that read/write in binary mode and normalize newlines (`replace(b'\r\n', b'\n').replace(b'\n', b'\r\n')`) to prevent file corruption.
